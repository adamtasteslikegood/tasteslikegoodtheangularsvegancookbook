## Overview

This directory is the project's documentation and source-area index that organizes server runtime entry points, route-classification logic, UI components, and related tests and public assets. At the root level there are currently no files; instead, the directory groups implementation and runtime artifacts into focused subdirectories. The server/ subdirectory contains the server-side runtime entry point (index.ts), a centralized route-classification manifest with helpers (route-manifest.ts), unit tests, and a public assets directory used for static pages. The src/ subdirectory is the home for source documentation and UI component implementations; it currently contains no root files and is expected to organize components into per-component subfolders.

Together, these subdirectories provide a clear separation between the server runtime surface and the UI/component source documentation. The server/ area supplies the runtime entry and routing/metering decisions that map incoming requests to behavior, while src/ holds UI components and their documentation so that the application UI and its docs are co-located. This structure supports focused developer workflows: backend/runtime changes and routing logic are primarily in server/, while UI work and component-level docs live under src/. Tests and public assets associated with server runtime are colocated inside server/ to keep runtime verification and static pages together.


### File Organization

Files are organized into subdirectories by concern: server/ holds runtime entry point, route-classification manifest, unit tests, and public static assets; src/ contains UI components and documentation organized into component-specific folders. The root contains no files and acts as an index for these focused areas.
