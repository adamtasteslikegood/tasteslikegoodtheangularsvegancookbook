## Overview

This module defines a centralized route-classification manifest and the runtime helpers that map incoming Express requests to routing and metering decisions. It exposes small interfaces describing route classifications and limiter names, and a set of pure functions that determine whether a path is a page subresource, whether it looks like a static asset, compute an absolute request path, classify a path against the manifest, and finally map a Request to a single metering class. The manifest and utilities are consumed by security and routing code to decide rate limiting exemptions and whether unknown asset-like paths should be treated as 404s rather than served the SPA HTML.

## Architecture Notes

- Single authoritative manifest used at runtime by both security and routing logic
- Separation of pure classification helpers (path-based tests) from request-level classification (express Request-aware)
- Interfaces used to convey classification and limiter identity rather than concrete classes

## Maintenance Notes

- Declare the route classification types via RouteClass, RequestClass, and LimiterName so callers can reason about routing and metering decisions.
- Provide isPageSubresource and matchesSubresource to detect static subresources that should not increment page counters.
- Provide looksLikeStaticAsset to heuristically determine whether a path resembles a static asset.
- Expose classifyRoute and absoluteRequestPath to map request paths to route classifications and to compute an absolute path independent of middleware mounting.
- Expose classifyRequest and isExemptFrom to assign every Request to exactly one metering class and to ask whether a given limiter exempts that request.
