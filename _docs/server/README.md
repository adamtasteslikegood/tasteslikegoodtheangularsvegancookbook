## Overview

This directory groups the code and tests responsible for bootstrapping and validating server-side HTTP behavior. At the root level it contains an index module that wires together server startup and shutdown responsibilities for an Express-based HTTP server, a module centralizing the decision about how many proxy hops Express should trust when resolving client IPs, and two test modules that exercise Datadog RUM plumbing and trust-proxy handling. The tests validate runtime configuration, same-origin intake proxy behavior, and Content Security Policy invariants related to that proxy as well as trust-proxy behavior.

Together these files provide the runtime entry point for the server (index.ts), a focused policy module for proxy/trust decisions (trust-proxy.ts), and test coverage to ensure the RUM and proxy decisions behave correctly (rum.test.ts and trust-proxy.test.ts). This directory's role in the larger system is to host the server runtime wiring and the specific, security- and observability-focused tests that ensure client IP resolution and RUM intake proxying conform to the project expectations.


### File Organization

Files are organized at the directory root by responsibility: index.ts as the server entry and lifecycle wiring, trust-proxy.ts as a focused policy module, and two test files (rum.test.ts and trust-proxy.test.ts) colocated with the code they validate. This flat layout keeps server runtime code and its related tests easy to discover together.

## Architecture Notes

- Proxy trust decisions are centralized in a single module (trust-proxy.ts) to avoid duplication and ensure consistent behavior across server startup and tests.
- Server lifecycle (startup/shutdown) is wired through a single entry module (index.ts) so that tests can exercise runtime configuration and the same-origin intake proxy consistently.
