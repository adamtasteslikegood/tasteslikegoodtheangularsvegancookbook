## What is working — keep it

- 🟢 `robots.txt` allows crawling, explicitly allows recipe images under `/api/recipes/*/image`, and declares the sitemap. Staging is `noindex` (KAN-182).
- 🟢 `sitemap.xml` is generated from the database: 98 URLs (home, browse, 96 recipes) with `lastmod`; submitted to the `tasteslikegood.org` Domain property on 2026-07-19 (KAN-115). Google re-reads it on its own.
- 🟢 Canonicals on every page; apex → www and http → https are single 301s; unknown `/r/` slugs return 404; `/browse/` 301s to `/browse`; known crawlers are exempt from the public-page rate limit (KAN-218).
- 🟢 **All 96 recipe pages carry complete `Recipe` JSON-LD**: image, `recipeYield`, `prepTime`/`cookTime`/`totalTime`, `recipeIngredient`, `HowToStep` instructions, `keywords`, author, dates. That meets Google's Recipe rich-result requirements. Average 417 words per page; alt text on 100% of images; one H1 per page.
- 🟢 Lighthouse on the SSR pages: the recipe page scores SEO 100, best practices 100, accessibility 100; `/browse` scores 92 / 100 / 100, the 92 being the robots.txt fetch artifact recorded in Appendix B. CLS 0 and total blocking time 0 ms on both; server response 120–170 ms. The "no ads, no autoplay, no tracking" stance is why — there is nothing third-party to slow the page down.
- 🟢 The home shell has title, description, Open Graph, Twitter card, `WebApplication` + `WebSite` JSON-LD, and a `<noscript>` nav to `/browse` and 8 hand-picked canonical recipes (KAN-114, KAN-116/158) guarded by a CI gate.
- 🟢 The brand already ranks for its own name across GitHub, Docker Hub, YouTube, Instagram and LinkedIn.

## Findings

Format: Issue · Impact · Evidence · Fix · Priority · Ticket.

### Technical

**T1 — Every page fails mobile LCP.** _Impact: High._ Lighthouse mobile lab: home LCP 6.1 s (FCP 6.0 s — nothing paints until the JS bundle runs), `/browse` 7.8 s (3,137 KB page, "improve image delivery" est. 2,941 KB), recipe 7.9 s (hero 1,070 KB, est. 1,056 KB). Sampled heroes: 935 KB, 1.59 MB, 924 KB, 959 KB, 1.78 MB, 1.03 MB, 1.44 MB, 2.01 MB, all 1408×768 JPEG. `recipe.html:38` lazy-loads the hero and gives it no `width`/`height`/`srcset`/`fetchpriority`. _Fix:_ sized WebP variants (1200/800/400 w) generated once and served through the existing image route with the same access check; hero `fetchpriority="high"`, explicit dimensions, no `loading="lazy"`; browse cards use the 400 w variant; `immutable` cache on versioned URLs. _Priority 1._ [KAN-271](https://tasteslikegood.atlassian.net/browse/KAN-271).

**T2 — Home shell ships ~800 KB of JavaScript before anything paints.** _Impact: High (home only)._ main 556 KB + chunk 257 KB; 546 KB unused on first paint; FCP 6.0 s. The SSR pages do not have this problem. _Fix:_ server-rendered hero copy (O1) gets content on screen before the bundle; then route-level code splitting and dropping unused code from the initial chunk. _Priority 2._ Folded into [KAN-272](https://tasteslikegood.atlassian.net/browse/KAN-272).

**T3 — SPA-only routes are indexable.** _Impact: Medium._ `/kitchen`, `/recipe/<uuid>`, `/about`, `/some-random-path` all return 200 with `index, follow`, `X-Robots-Tag: index, follow` and a canonical to `/`. `/kitchen` is private per-user UI; `/recipe/<id>` duplicates `/r/<slug>`; unknown paths are soft-404s (KAN-160 fixed only asset-like paths). _Fix:_ `X-Robots-Tag: noindex, follow` on the SPA catch-all for every path except `/`; optionally 404 unknown HTML paths. _Priority 3._ [KAN-276](https://tasteslikegood.atlassian.net/browse/KAN-276).

**T4 — `/r/<slug>/` returns 404 instead of redirecting.** _Impact: Low._ Trailing-slash links from third parties would dead-end. _Fix:_ 301 to the canonical. _Priority 4._ In [KAN-273](https://tasteslikegood.atlassian.net/browse/KAN-273).

**T5 — SSR responses are `Cache-Control: private`.** _Impact: Low today._ No CDN caching, but TTFB is already 120–170 ms. Note for when traffic exists; nothing to do now.

**T6 — No field Core Web Vitals.** _Impact: informational._ CrUX has no rows for a site this young; Search Console's Core Web Vitals report will populate once there is traffic. A free PageSpeed Insights API key (GCP console → APIs → PageSpeed Insights) makes lab runs repeatable from a routine; optional.

### On-page

**O1 — The home page has nothing for Google to rank for "vegan recipe generator".** _Impact: High._ Server HTML: no `<h1>` (the only H1, "VeganGenius Chef", is JavaScript-rendered), 42 words, `<title>` 83 characters (results truncate near 60), meta description 182 characters (near 160). The generator UI is an input and a button with no explanatory copy; competitors that rank surround the tool with an H1, "how it works" and an FAQ. On-page checker: 55/100 versus 92/100 for recipe pages. _Fix:_ title "Free AI Vegan Recipe Generator & Cookbook | TastesLikeGood" (58 chars); description ≈155 chars leading with the no-ads/no-life-story promise; a **visible**, server-rendered `<h1>Vegan Recipe Generator</h1>` with 150–300 words and a 4–6 question FAQ (`FAQPage` JSON-LD); header nav as real links. _Priority 1._ [KAN-272](https://tasteslikegood.atlassian.net/browse/KAN-272).

**O2 — Recipe pages are crawl dead-ends.** _Impact: High._ Every `/r/<slug>` page links to 0 other recipes (only "← Browse all recipes" and the header). No breadcrumb, no related recipes, no category link. Link equity from any future backlink stops at that one page. _Fix:_ "More vegan recipes" block (4–6 by shared tags) with real anchors, `BreadcrumbList` JSON-LD + visible breadcrumb, category derived from tags. _Priority 2._ [KAN-273](https://tasteslikegood.atlassian.net/browse/KAN-273).

**O3 — Titles and descriptions get truncated.** _Impact: Medium._ 25 of 96 recipe titles exceed 60 characters (longest 84: "Vegan Double Chocolate Chip Cookies with Baked-On Chocolate Drizzle · TastesLikeGood"); 47 descriptions exceed 160. The template appends " · TastesLikeGood" unconditionally. _Fix:_ drop the suffix when the name is over ~44 characters; cut descriptions at the last sentence boundary before 155. _Priority 3._ In [KAN-273](https://tasteslikegood.atlassian.net/browse/KAN-273).

**O4 — Social images are broken on the two pages people will share most.** _Impact: Medium._ Home `og:image`/`twitter:image` = `/favicon.svg` — SVG is ignored by Facebook, X, Slack, iMessage and LinkedIn unfurlers, so every share of the home page renders blank. `/browse` has no `og:image` and a `summary` card. Recipe pages are fine (real 1408×768 JPEG). _Fix:_ one 1200×630 raster for home, the newest hero for browse. _Priority 3._ In [KAN-272](https://tasteslikegood.atlassian.net/browse/KAN-272) / [KAN-273](https://tasteslikegood.atlassian.net/browse/KAN-273).

**O5 — `/browse` is thin as a landing page.** _Impact: Medium._ Title 37 chars ("Browse Vegan Recipes · TastesLikeGood"), description 65 chars, no JSON-LD, eyebrow "Anti-recipe browse". It is the second-most linked page on the site and the parent of every hub. _Fix:_ `CollectionPage` + `ItemList` JSON-LD, a title with the live count ("Browse 96 Vegan Recipes with Photos"), a 150-char description that says "AI-generated vegan recipes, one photo each, no ads". _Priority 3._ In [KAN-273](https://tasteslikegood.atlassian.net/browse/KAN-273).

**O6 — Dead `SearchAction`.** _Impact: Low._ `WebSite` JSON-LD promises `/?q={search_term_string}`; the SPA ignores `q`. Google may test it. _Fix:_ remove until `/browse?q=` exists (Sprint 10 filter/sort scope), then point it there. In [KAN-272](https://tasteslikegood.atlassian.net/browse/KAN-272).

**O7 — `recipeCategory` is hard-coded "Vegan"; no `recipeCuisine`.** _Impact: Low._ Tags already carry the course (breakfast, dessert, sandwich…) and cuisine (mexican, italian, korean, vietnamese…). _Fix:_ a small tag → category/cuisine map in `_recipe_json_ld`; keep Vegan as `suitableForDiet`. In [KAN-273](https://tasteslikegood.atlassian.net/browse/KAN-273).

### Content

**C1 — No category or hub pages.** _Impact: High._ Google autocomplete for the site's second keyword family is category-shaped ("vegan dinner ideas easy", "easy vegan recipes for beginners", "vegan recipes with tofu"); no single recipe can rank for those, and there is no page that aggregates them. The catalog already has the tags (exact-tag counts over all 96 pages, recomputed 2026-09-13): comfort food 23, dinner 23, gluten-free 20, dessert 16, breakfast 14 (plus 9 brunch), lunch 14, tofu 12, sandwich 11, snack 11, appetizer 10, pasta 9 and italian 7, mexican 7 and tacos 6, seitan 9, high protein 5 (8 counting variants). _Fix:_ `/browse/tag/<tag>` for an allow-listed set, self-canonical, in the sitemap, with 80–150 words of intro each; `noindex` any hub under 3 recipes. _Priority 2._ [KAN-274](https://tasteslikegood.atlassian.net/browse/KAN-274).

**C2 — Duplicates and cannibalization (KAN-157 recurrence).** _Impact: High._ `vegan-banana-apple-cider-oatmeal-raisin-cookies-2` and `vegan-zucchini-poppers-2` are statistically identical to their originals (same ingredient, step and word counts, same description); `vegan-fried-pizza-dough-with-powdered-sugar-2` has no public original. Three cornbreads (the still-open decision from the canonical rollout; `vegan-cornbread` is a home-page canonical anchor and the thinnest page on the site at 241 words with a 44-character description). Near-pairs competing for one query: three chicken/country-fried steaks, two English breakfasts, two blooming onions, two double-doubles, three baked zitis. _Fix:_ unpublish the two identical `-2` copies now; decide the cornbread and pizza-dough canonicals; pick one page per near-pair to link from hubs; block `-\d` slugs at publish time. _Priority 2._ [KAN-275](https://tasteslikegood.atlassian.net/browse/KAN-275).

**C3 — Engineering-joke titles: Adam's decision, not a recommendation.** _Impact: Medium for those pages only._ Eight public recipes are named for the codebase (`full-stack-cloud-architecture-prd-pancakes`, `error-handling-black-bean-burgers`, `the-rate-limited-open-faced-tempeh-club`, `vegan-pub-sub-turkey-bacon-club-sandwich`, `type-checked-tex-mex-chex-mix`, `no-tariff-tofu-salad-sandwiches`, `heisenberg-s-blue-corn-biscuits…`, `vegan-happy-meal-tofu-nuggets…`). They fail the canonical rubric's hard gate 4 and match no query, but they are the brand's voice. Options: keep as-is; keep the page but give the title/H1 a searchable name with the joke as a subtitle (recommended); unpublish. Recorded on [KAN-275](https://tasteslikegood.atlassian.net/browse/KAN-275).

**C4 — Seven thin pages under 300 words.** _Impact: Low._ `vegan-cornbread` 241, `classic-vegan-s-mores` 255 (3 ingredients), `vegan-mushroom-coffee-protein-smoothie` 263, `creamy-vegan-hot-cocoa` 276, `sparkling-iced-yuzu-matcha` 290, `vegan-peach-lemon-lime-popsicles` 293, `elegant-vegan-avocado-toast-for-high-tea` 294. _Fix:_ a chef's-notes paragraph (substitutions, storage, serving) lifts each past 300 with real value; the generator can draft them. No ticket — fold into the next content pass.

**C5 — No About or author page.** _Impact: Medium for E-E-A-T._ Author is "Adam Schoen" as a `Person` with no URL; there is a privacy policy but no About page explaining who makes the site and why there are no ads. The "anti-recipe site" manifesto is the About page and the Show HN post at once. _Fix:_ `/about` (server-rendered static HTML like the privacy policy) + `Person` schema with `sameAs` to GitHub, LinkedIn, YouTube, Instagram; link it from the footer. Add to [KAN-272](https://tasteslikegood.atlassian.net/browse/KAN-272).

### Off-site

## Competitive snapshot (US, 2026-09-13)

"vegan recipe generator": Jungle of Veggies (Webflow site with an AI generator), One Ingredient Chef, a random-picker page on arimotravels.com, 10weeks.org (an H1 and a search box, no copy at all), ReceptoAI, RipePlate's vegan category, MyChefAI `/veg`, an AIPRM prompt, Simple Veganista's by-ingredient index, an iOS app. "AI vegan recipe generator free": MyChefAI, DishGen, FromYourFridge, RecipeGrids, ReceptoAI — and tasteslikegood.org.

What that says: the query is served by thin tool pages and generic AI generators with a vegan toggle. Nobody in that set has 96 published recipes with photos and full `Recipe` markup, and nobody sells "no ads, no life story, no paywall". The gap is entirely presentational: they have an H1, a "how it works", an FAQ and the word "free" in the title; the home page has none of those. That is KAN-272, and it is the highest-leverage change on this list.

## How to grow visibility and backlinks

1. **Make the home page rankable first** (KAN-272). Nothing off-site is worth doing until a share of the home page shows an image and a headline.
2. **Owned properties, one hour** (KAN-277): GitHub `homepage` + topics + README link on both repos, Docker Hub description, YouTube "About", Instagram bio, LinkedIn project. These are the only links the site controls outright.
3. **Pinterest** (KAN-277): verify the domain, then pin ten recipes. The site already emits Rich-Pin data; Pinterest is the one social network where recipe images are the product.
