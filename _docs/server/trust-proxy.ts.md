## Overview

This module documents and centralizes the decision about how many proxy hops Express should trust when resolving req.ip. It explains that production traffic arrives through a Google external Application Load Balancer (ALB) which appends ". . . <client-ip>, <lb-ip>" to the X-Forwarded-For header. Because the last entry is the load balancer’s frontend address, Express must be configured to trust two hops so that the client IP is taken from the second-to-last entry rather than the LB address. The file also records the operational implication that if ingress is later opened to direct run.app traffic the same trust count would be incorrect and would need to be changed in tandem with any ingress configuration.
