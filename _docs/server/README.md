## Overview

This directory provides the server-side runtime surface and the route-classification logic used to map incoming requests to routing and metering decisions. At the root level there is an entry point (index.ts) for the server runtime, a centralized manifest with runtime helpers (route-manifest.ts), and two Vitest-based test modules (about-page.test.ts and route-manifest.test.ts) that validate the checked-in /about static page content and the route-classification manifest respectively.

The public/ subdirectory holds static, public-facing assets that the server exposes directly to clients; specifically it contains the about.html page which is the complete About page for the site. Together, the root files implement runtime routing and the manifest logic while tests exercise those behaviors and the public/ subdirectory supplies the static content that some routes serve. This structure keeps the runtime entry point and routing logic co-located with tests and the static assets they validate, making it straightforward to understand how requests are classified and which static pages are served.


### File Organization

Root-level TypeScript modules implement runtime entry (index.ts) and routing logic (route-manifest.ts), while test files sharing the same directory validate those modules. A single subdirectory (public/) holds static assets served by the server. This keeps server runtime code, its tests, and static content grouped together for focused development and testing.

## Architecture Notes

- A centralized route-classification manifest (route-manifest.ts) centralizes routing and metering decisions so the server entry point (index.ts) can remain focused on startup and request handling.
- Tests are colocated with the server code to provide quick feedback on routing logic and the integrity of checked-in static pages.
